# [HU-02] Administrar catálogo de tipologías y categorías de vehículos

**Dado:** Administrador autorizado.
**Para:** mantener las tipologías y categorías de vehículos admitidas.
**Que:** permitir que los registros vehiculares utilicen valores válidos y consistentes.

**Flujo esperado**
1. El administrador consulta el catálogo vigente de tipos y categorías.
2. El sistema valida permisos y estructura de los cambios.
3. Los cambios válidos se guardan y quedan disponibles para MOD-02.
4. Las opciones desactivadas dejan de ofrecerse para nuevos registros sin alterar el historial.

**Criterios de aceptación**
- [ ] Solo usuarios autorizados pueden modificar el catálogo.
- [ ] No se aceptan nombres o códigos duplicados.
- [ ] Los vehículos nuevos solo pueden asociarse a categorías activas.
- [ ] No se elimina directamente una categoría que tenga vehículos asociados.

**Endpoint:** `GET /api/v1/parametros/tipos-vehiculo` ; `POST /api/v1/parametros/tipos-vehiculo` ; `PUT /api/v1/parametros/tipos-vehiculo/{tipoVehiculoId}` ; `DELETE /api/v1/parametros/tipos-vehiculo/{tipoVehiculoId}` ; `GET /api/v1/parametros/categorias-vehiculo` ; `POST /api/v1/parametros/categorias-vehiculo` ; `PUT /api/v1/parametros/categorias-vehiculo/{categoriaId}` ; `DELETE /api/v1/parametros/categorias-vehiculo/{categoriaId}`

**Ejemplo de solicitud**
_POST /parametros/tipos-vehiculo_
```json
{
  "codigo": "AUTOMOVIL",
  "nombre": "Automóvil",
  "categoriaId": "CAT-01"
}
```
_PUT /parametros/tipos-vehiculo/{tipoVehiculoId}_
```json
{
  "codigo": "AUTOMOVIL",
  "nombre": "Automóvil",
  "categoriaId": "CAT-01",
  "activo": true
}
```

**Respuesta exitosa**
```json
{
  "exito": true,
  "mensaje": "Catálogo de tipos de vehículo consultado exitosamente",
  "datos": [
    {
      "tipoVehiculoId": "TV-01",
      "codigo": "AUTOMOVIL",
      "nombre": "Automóvil",
      "categoriaId": "CAT-01",
      "activo": true
    }
  ],
  "fechaHora": "2026-10-23T12:00:00-05:00"
}
```

**Notas técnicas:** `GET /api/v1/parametros/tipos-vehiculo` figura en el documento base; las rutas de escritura y de categorías son propuesta del equipo. Rutas, campos y mensajes son propuesta del equipo; se confirman en el Inventario de APIs (punto 4). La parametrización no invalida registros históricos: desactivar un tipo no modifica vehículos ya registrados.

**Errores específicos de esta historia**

| Código | Cuándo ocurre | Mensaje (`mensaje`) |
|---|---|---|
| 422 Unprocessable Entity | Duplicado por `codigo` o eliminación de un elemento con dependencias activas (vehículos de MOD-02). | No es posible completar la operación: el elemento está duplicado o en uso |

**Requisitos de pruebas**

| Caso | Precondición | Acción exacta | Resultado esperado |
|---|---|---|---|
| Consulta autorizada del catálogo de tipos de vehículo | Administrador autenticado con JWT vigente; existen tipos de vehículo registrados. | GET /api/v1/parametros/tipos-vehiculo con Authorization: Bearer <TOKEN_ADMIN>. | 200 OK; exito = true; datos contiene el catálogo vigente de tipos de vehículo con sus campos tipoVehiculoId y activo. |
| Creación válida de tipo de vehículo | Administrador autenticado; no existe un elemento con el mismo codigo. | POST /api/v1/parametros/tipos-vehiculo con el cuerpo de ejemplo. | 201 Created; exito = true; datos.tipoVehiculoId generado por el sistema.; Una consulta posterior GET /api/v1/parametros/tipos-vehiculo incluye el nuevo elemento. |
| Eliminación de tipo de vehículo sin dependencias | Existe un tipo de vehículo sin registros asociados (vehículos de MOD-02). | DELETE /api/v1/parametros/tipos-vehiculo/{tipoVehiculoId}. | 200 OK; exito = true; El elemento deja de aparecer en el catálogo. |
| Usuario sin permisos administrativos | Usuario autenticado con rol CLIENTE. | POST /api/v1/parametros/tipos-vehiculo con el cuerpo de ejemplo. | 403 Forbidden; exito = false; Mensaje: "Acceso denegado: se requieren permisos de Administrador".; No se modifica ningún dato. |
| Solicitud sin token | Sin cabecera Authorization. | GET /api/v1/parametros/tipos-vehiculo. | 401 Unauthorized; exito = false; Mensaje: "No autenticado: token ausente o inválido". |
| Duplicado por `codigo` | Ya existe un tipo de vehículo con el mismo codigo. | POST /api/v1/parametros/tipos-vehiculo repitiendo codigo. | 422 Unprocessable Entity; exito = false; Mensaje que identifica el campo duplicado codigo.; No se crea un segundo registro. |
| Dato obligatorio ausente o inválido | Administrador autenticado. | POST /api/v1/parametros/tipos-vehiculo sin el campo nombre. | 422 Unprocessable Entity; exito = false; El mensaje identifica el campo nombre. |

Desactívelo."; El elemento conserva sus datos. |

## Elementos comunes
### Sobre estándar de respuesta (todas las APIs)

Campos: `exito` (boolean), `mensaje` (string), `datos` (objeto, arreglo o `null`), `fechaHora` (ISO 8601 con zona horaria). El cuerpo no sustituye el código HTTP. Todas las APIs usan `Content-Type: application/json` en operaciones con body y `Authorization: Bearer <JWT>` (salvo registro, login y el webhook de la pasarela, que se autentica con su firma).
