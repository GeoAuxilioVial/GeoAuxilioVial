# [HU-04] Administrar reglas, tipos de avería y criterios de auxilio vial

**Dado:** Administrador autorizado.
**Para:** mantener los tipos de avería y parámetros operativos del auxilio vial.
**Que:** adaptar el catálogo de atención a las necesidades del servicio sin cambiar el código fuente.

**Flujo esperado**
1. El administrador consulta las reglas y tipos de avería disponibles.
2. El sistema diferencia parámetros editables de reglas fijas del dominio.
3. Se validan y guardan los cambios permitidos.
4. MOD-05 consume los parámetros vigentes al gestionar solicitudes.

**Criterios de aceptación**
- [ ] Solo administradores autorizados pueden modificar los catálogos.
- [ ] Los tipos de avería deben tener identificador y descripción válidos.
- [ ] Las reglas fijas del dominio no se modifican como simples parámetros.
- [ ] No se eliminan tipos utilizados por solicitudes históricas o activas.

**Endpoint:** `GET /api/v1/parametros/tipos-averia` ; `POST /api/v1/parametros/tipos-averia` ; `PUT /api/v1/parametros/tipos-averia/{tipoAveriaId}` ; `DELETE /api/v1/parametros/tipos-averia/{tipoAveriaId}` ; `GET /api/v1/parametros/reglas-auxilio` ; `POST /api/v1/parametros/reglas-auxilio` ; `PUT /api/v1/parametros/reglas-auxilio/{reglaId}` ; `DELETE /api/v1/parametros/reglas-auxilio/{reglaId}`

**Ejemplo de solicitud**
_POST /parametros/tipos-averia_
```json
{
  "codigo": "BATERIA",
  "descripcion": "Batería descargada"
}
```
_PUT /parametros/tipos-averia/{tipoAveriaId}_
```json
{
  "codigo": "BATERIA",
  "descripcion": "Batería descargada",
  "activo": true
}
```

**Respuesta exitosa**
```json
{
  "exito": true,
  "mensaje": "Catálogo de tipos de avería consultado exitosamente",
  "datos": [
    {
      "tipoAveriaId": "AV-01",
      "codigo": "BATERIA",
      "descripcion": "Batería descargada",
      "activo": true
    }
  ],
  "fechaHora": "2026-10-23T12:00:00-05:00"
}
```

**Notas técnicas:** Rutas, campos y mensajes son propuesta del equipo; se confirman en el Inventario de APIs (punto 4). El campo `editable` distingue parámetros configurables de invariantes del dominio (propuesta). Ejemplos de claves como `TIEMPO_MAX_RESPUESTA_SEG` son propuesta; el tiempo de respuesta lo consume HU-20.

**Errores específicos de esta historia**

| Código | Cuándo ocurre | Mensaje (`mensaje`) |
|---|---|---|
| 422 Unprocessable Entity | Duplicado por `codigo` o eliminación de un elemento con dependencias activas (solicitudes de auxilio de MOD-05). | No es posible completar la operación: el elemento está duplicado o en uso |
| 422 Unprocessable Entity | Intento de modificar una regla con `editable` = `false`. | Regla fija del dominio: no puede modificarse como parámetro |

**Requisitos de pruebas**

| Caso | Precondición | Acción exacta | Resultado esperado |
|---|---|---|---|
| Consulta autorizada del catálogo de tipos de avería | Administrador autenticado con JWT vigente; existen tipos de avería registrados. | GET /api/v1/parametros/tipos-averia con Authorization: Bearer <TOKEN_ADMIN>. | 200 OK; exito = true; datos contiene el catálogo vigente de tipos de avería con sus campos tipoAveriaId y activo. |

| Usuario sin permisos administrativos | Usuario autenticado con rol CLIENTE. | POST /api/v1/parametros/tipos-averia con el cuerpo de ejemplo. | 403 Forbidden; exito = false; Mensaje: "Acceso denegado: se requieren permisos de Administrador".; No se modifica ningún dato. |

Desactívelo."; El elemento conserva sus datos. |

## Elementos comunes
### Sobre estándar de respuesta (todas las APIs)

Campos: `exito` (boolean), `mensaje` (string), `datos` (objeto, arreglo o `null`), `fechaHora` (ISO 8601 con zona horaria). El cuerpo no sustituye el código HTTP. Todas las APIs usan `Content-Type: application/json` en operaciones con body y `Authorization: Bearer <JWT>` (salvo registro, login y el webhook de la pasarela, que se autentica con su firma).
