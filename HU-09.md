# [HU-09] Gestionar perfiles de usuario aplicando permisos y visibilidad según rol asignado

**Dado:** Usuario autenticado.
**Para:** consultar y actualizar los datos de mi perfil.
**Que:** mantener mi información vigente sin acceder a datos de otras personas ni modificar campos no permitidos.

**Flujo esperado**
1. El cliente envía el JWT en Authorization: Bearer.
2. El servicio valida firma, expiración e identidad.
3. Para consulta, devuelve solo los campos permitidos al rol.
4. Para actualización, valida los campos editables y persiste los cambios.
5. Devuelve el perfil actualizado con el sobre estándar.

**Criterios de aceptación**
- [ ] GET devuelve únicamente el perfil asociado al token.
- [ ] PUT solo acepta campos editables documentados.
- [ ] Token ausente o inválido no permite consultar ni modificar.
- [ ] Campos desconocidos o no autorizados se rechazan sin cambios parciales.
- [ ] El correo y el rol no se cambian mediante este endpoint si no existe un flujo específico.

**Endpoint:** `GET /api/v1/perfil` ; `PUT /api/v1/perfil`

**Ejemplo de solicitud**
```json
{
  "actualizacion": {
    "nombre": "Ana Pérez",
    "telefono": "+573001112233"
  }
}
```

**Respuesta exitosa**
```json
{
  "exito": true,
  "mensaje": "Perfil consultado correctamente",
  "datos": {
    "id": "usr_123",
    "nombre": "Ana Pérez",
    "correo": "ana@example.com",
    "telefono": "+573001112233",
    "roles": [
      "CLIENTE"
    ]
  },
  "fechaHora": "2026-10-23T12:00:00-05:00"
}
```

**Notas técnicas:** autorización por identidad y rol; aplicar lista permitida de campos actualizables. Evitar asignación masiva de atributos.

**Requisitos de pruebas**

| Caso | Precondición | Acción exacta | Resultado esperado |
|---|---|---|---|
| Consulta autorizada | JWT válido de usr_123. | GET /api/v1/perfil con Bearer token válido. | 200 OK; datos.id corresponde a usr_123. |
| Actualización válida | JWT válido y perfil existente. | PUT /api/v1/perfil con nombre y teléfono válidos. | 200 OK; datos refleja los cambios persistidos. |
| Token ausente | No se envía Authorization. | GET /api/v1/perfil sin token. | 401 Unauthorized; no se devuelve información del perfil. |
| Campo no permitido | JWT válido. | PUT /api/v1/perfil con {"roles":["ADMIN"]}. | 422 Unprocessable Entity; roles no cambia. |

**Trazabilidad:** `MOD-01`, `FUN-02`, `PRO-02`

## Elementos comunes
### Sobre estándar de respuesta (todas las APIs)

Campos: `exito` (boolean), `mensaje` (string), `datos` (objeto, arreglo o `null`), `fechaHora` (ISO 8601 con zona horaria). El cuerpo no sustituye el código HTTP. Todas las APIs usan `Content-Type: application/json` en operaciones con body y `Authorization: Bearer <JWT>` (salvo registro, login y el webhook de la pasarela, que se autentica con su firma).
