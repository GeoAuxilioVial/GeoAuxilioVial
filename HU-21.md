# [HU-21] Realizar seguimiento cartográfico en vivo del desplazamiento del auxilio

**Dado:** Cliente y proveedor participantes del auxilio.
**Para:** consultar el estado y registrar transiciones autorizadas del servicio.
**Que:** hacer seguimiento desde la asignación hasta la finalización.

**Flujo esperado**
1. El participante consulta el detalle de la solicitud.
2. El proveedor registra una transición permitida, como EN_CAMINO o EN_SERVICIO.
3. El backend valida actor, estado actual y transición permitida.
4. Se guarda evento de estado con fecha y actor.
5. El cliente consulta el nuevo estado y la cronología.

**Criterios de aceptación**
- [ ] Solo participantes o administradores autorizados consultan la solicitud.
- [ ] Cada transición se valida contra la máquina de estados.
- [ ] Se conserva historial inmutable de cambios de estado.
- [ ] No se permite retroceder a estados incompatibles.
- [ ] Un identificador inexistente devuelve 404.

**Endpoint:** `GET /api/v1/auxilio/solicitudes/{solicitudId}` ; `PATCH /api/v1/auxilio/solicitudes/{solicitudId}/estado`

**Ejemplo de solicitud**
```json
{
  "nuevoEstado": "EN_CAMINO",
  "observacion": "Proveedor inició desplazamiento"
}
```

**Respuesta exitosa**
```json
{
  "exito": true,
  "mensaje": "Estado de solicitud actualizado",
  "datos": {
    "solicitudId": "aux_456",
    "estado": "EN_CAMINO",
    "actualizadoEn": "2026-10-23T12:10:00-05:00"
  },
  "fechaHora": "2026-10-23T12:00:00-05:00"
}
```

**Notas técnicas:** el servidor debe ser autoridad sobre la máquina de estados. El cliente no puede fijar libremente el estado ni la marca de tiempo.

**Requisitos de pruebas**

| Caso | Precondición | Acción exacta | Resultado esperado |
|---|---|---|---|
| Transición válida | Solicitud ACEPTADA; token del proveedor asignado. | PATCH /api/v1/auxilio/solicitudes/aux_456/estado con nuevoEstado=EN_CAMINO. | 200 OK; estado y evento quedan guardados. |
| Transición inválida | Solicitud CANCELADA. | PATCH intentando pasar a EN_SERVICIO. | 422 Unprocessable Entity; estado no cambia. |
| Participante ajeno | Token de usuario que no participa. | GET /api/v1/auxilio/solicitudes/aux_456. | 403 Forbidden o 404; datos no expuestos. |
| Solicitud inexistente | No existe aux_999. | GET /api/v1/auxilio/solicitudes/aux_999. | 404 Not Found. |

**Trazabilidad:** `MOD-05`, `FUN-14`, `PRO-14`

## Elementos comunes
### Sobre estándar de respuesta (todas las APIs)

Campos: `exito` (boolean), `mensaje` (string), `datos` (objeto, arreglo o `null`), `fechaHora` (ISO 8601 con zona horaria). El cuerpo no sustituye el código HTTP. Todas las APIs usan `Content-Type: application/json` en operaciones con body y `Authorization: Bearer <JWT>` (salvo registro, login y el webhook de la pasarela, que se autentica con su firma).
