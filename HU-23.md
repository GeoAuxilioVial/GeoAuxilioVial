# [HU-23] Agendar y confirmar citas de mantenimiento preventivo con talleres mecánicos aliados

**Dado:** Propietario de un vehículo.
**Para:** consultar disponibilidad y agendar una cita en un taller aliado.
**Que:** programar el mantenimiento preventivo de mi vehículo.

**Flujo esperado**
1. El usuario selecciona vehículo, tipo de mantenimiento, taller y horario disponible.
2. El sistema valida propiedad del vehículo y disponibilidad del taller.
3. La cita se registra con el estado inicial definido por el flujo.
4. El sistema devuelve la confirmación o informa que el horario ya no está disponible.

**Criterios de aceptación**
- [ ] Solo el propietario o usuario autorizado puede agendar para el vehículo.
- [ ] La cita debe referenciar un taller aliado habilitado (HU-03) y un horario válido.
- [ ] No se confirman dos citas incompatibles para el mismo espacio disponible.
- [ ] La respuesta informa el estado de la cita y los datos necesarios para consultarla.

**Endpoint:** `GET /api/v1/mantenimiento/talleres/{tallerId}/disponibilidad` ; `POST /api/v1/mantenimiento/citas`

**Ejemplo de solicitud**
```json
{
  "vehiculoId": "VEH-0001",
  "tallerId": "TAL-001",
  "planId": "PM-01",
  "fechaHora": "2026-11-05T09:00:00"
}
```

**Respuesta exitosa**
```json
{
  "exito": true,
  "mensaje": "Cita registrada exitosamente",
  "datos": {
    "citaId": "CIT-0001",
    "estado": "PENDIENTE_CONFIRMACION",
    "tallerId": "TAL-001",
    "fechaHora": "2026-11-05T09:00:00"
  },
  "fechaHora": "2026-10-23T12:00:00-05:00"
}
```

**Notas técnicas:** `POST /api/v1/mantenimiento/citas` figura en la lista de APIs; la consulta de disponibilidad y los campos son propuesta del equipo. Rutas, campos y mensajes son propuesta del equipo; se confirman en el Inventario de APIs (punto 4). El rol y la integración del taller aliado (portal propio o API) siguen sin definir.

**Errores específicos de esta historia**

| Código | Cuándo ocurre | Mensaje (`mensaje`) |
|---|---|---|
| 409 Conflict | El horario del taller ya está ocupado. | El horario ya no está disponible; elija otro |
| 422 Unprocessable Entity | Taller no habilitado o plan inexistente. | El taller no está habilitado para agendar |

**Requisitos de pruebas**

| Caso | Precondición | Acción exacta | Resultado esperado |
|---|---|---|---|
| Horario disponible | Cliente propietario; taller habilitado con el horario libre. | POST /api/v1/mantenimiento/citas con el cuerpo de ejemplo. | 201 Created; exito = true; datos.citaId y datos.estado según el flujo. |
| Horario ocupado | El horario ya tiene una cita confirmada. | POST /api/v1/mantenimiento/citas con el mismo fechaHora. | 409 Conflict; exito = false; Mensaje: "El horario ya no está disponible; elija otro".; La cita no se duplica. |
| Vehículo no autorizado | El vehículo pertenece a otro usuario. | POST /api/v1/mantenimiento/citas con vehiculoId = VEH-0500. | 403 Forbidden; exito = false; No se registra la cita. |
| Taller no habilitado | El taller está deshabilitado (HU-03). | POST /api/v1/mantenimiento/citas con tallerId = TAL-009. | 422 Unprocessable Entity; exito = false; Mensaje: "El taller no está habilitado para agendar". |
| Consulta de disponibilidad | Taller habilitado. | GET /api/v1/mantenimiento/talleres/TAL-001/disponibilidad?fecha=2026-11-05. | 200 OK; datos.horarios lista solo espacios libres. |

**Trazabilidad:** `MOD-06`, `FUN-16`, `PRO-16`

## Elementos comunes
### Sobre estándar de respuesta (todas las APIs)

Campos: `exito` (boolean), `mensaje` (string), `datos` (objeto, arreglo o `null`), `fechaHora` (ISO 8601 con zona horaria). El cuerpo no sustituye el código HTTP. Todas las APIs usan `Content-Type: application/json` en operaciones con body y `Authorization: Bearer <JWT>` (salvo registro, login y el webhook de la pasarela, que se autentica con su firma).
