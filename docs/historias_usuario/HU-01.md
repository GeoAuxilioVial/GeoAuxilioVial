# [HU-01] Administrar catálogos y tipos de usuarios/roles

**Dado:** Administrador autorizado.
**Para:** consultar, crear, actualizar o desactivar los tipos de usuario y roles disponibles.
**Que:** mantener centralizados los perfiles y permisos que utiliza la plataforma.

**Flujo esperado**
1. El administrador abre la sección de parametrización de usuarios y roles.
2. El sistema valida el JWT y comprueba que contenga el rol `ADMINISTRADOR`.
3. El administrador consulta o envía los cambios del catálogo.
4. El sistema valida los datos, conserva los elementos con dependencias activas y publica la configuración vigente.

**Criterios de aceptación**
- [ ] Solo los administradores autorizados pueden gestionar el catálogo.
- [ ] Los campos obligatorios y los identificadores únicos se validan antes de guardar.
- [ ] Los cambios válidos quedan persistidos y disponibles para los módulos que consumen el catálogo.
- [ ] No se permite eliminar un rol asociado a usuarios activos; debe desactivarse.

**Endpoint:** `GET /api/v1/parametros/roles` ; `POST /api/v1/parametros/roles` ; `PUT /api/v1/parametros/roles/{rolId}` ; `DELETE /api/v1/parametros/roles/{rolId}`

**Ejemplo de solicitud**
_POST /parametros/roles_
```json
{
  "nombre": "CLIENTE",
  "descripcion": "Usuario que solicita auxilio vial"
}
```
_PUT /parametros/roles/{rolId}_
```json
{
  "nombre": "CLIENTE",
  "descripcion": "Usuario que solicita auxilio vial",
  "activo": true
}
```

**Respuesta exitosa**
```json
{
  "exito": true,
  "mensaje": "Catálogo de roles consultado exitosamente",
  "datos": [
    {
      "rolId": "ROL-01",
      "nombre": "CLIENTE",
      "descripcion": "Usuario que solicita auxilio vial",
      "activo": true
    }
  ],
  "fechaHora": "2026-10-23T12:00:00-05:00"
}
```

**Notas técnicas:** Rutas, campos y mensajes son propuesta del equipo; se confirman en el Inventario de APIs (punto 4). El rol «Administrador» se denomina `ADMINISTRADOR` en el claim `rol` del JWT (propuesta). Un rol desactivado deja de ofrecerse para nuevos usuarios, pero los usuarios que ya lo tienen lo conservan.

**Errores específicos de esta historia**

| Código | Cuándo ocurre | Mensaje (`mensaje`) |
|---|---|---|
| 422 Unprocessable Entity | Duplicado por `nombre` o eliminación de un elemento con dependencias activas (usuarios activos de MOD-01). | No es posible completar la operación: el elemento está duplicado o en uso |

**Requisitos de pruebas**

| Caso | Precondición | Acción exacta | Resultado esperado |
|---|---|---|---|
| Consulta autorizada del catálogo de roles | Administrador autenticado con JWT vigente; existen roles registrados. | GET /api/v1/parametros/roles con Authorization: Bearer <TOKEN_ADMIN>. | 200 OK; exito = true; datos contiene el catálogo vigente de roles con sus campos rolId y activo. |
| Creación válida de rol | Administrador autenticado; no existe un elemento con el mismo nombre. | POST /api/v1/parametros/roles con el cuerpo de ejemplo. | 201 Created; exito = true; datos.rolId generado por el sistema.; Una consulta posterior GET /api/v1/parametros/roles incluye el nuevo elemento. |
| Eliminación de rol sin dependencias | Existe un rol sin registros asociados (usuarios activos de MOD-01). | DELETE /api/v1/parametros/roles/{rolId}. | 200 OK; exito = true; El elemento deja de aparecer en el catálogo. |
| Usuario sin permisos administrativos | Usuario autenticado con rol CLIENTE. | POST /api/v1/parametros/roles con el cuerpo de ejemplo. | 403 Forbidden; exito = false; Mensaje: "Acceso denegado: se requieren permisos de Administrador".; No se modifica ningún dato. |
| Solicitud sin token | Sin cabecera Authorization. | GET /api/v1/parametros/roles. | 401 Unauthorized; exito = false; Mensaje: "No autenticado: token ausente o inválido". |
| Duplicado por `nombre` | Ya existe un rol con el mismo nombre. | POST /api/v1/parametros/roles repitiendo nombre. | 422 Unprocessable Entity; exito = false; Mensaje que identifica el campo duplicado nombre.; No se crea un segundo registro. |
| Dato obligatorio ausente o inválido | Administrador autenticado. | POST /api/v1/parametros/roles sin el campo nombre. | 422 Unprocessable Entity; exito = false; El mensaje identifica el campo nombre. |
| Eliminación de rol en uso (dependencias activas) | El rol está referenciado por usuarios activos de MOD-01. | DELETE /api/v1/parametros/roles/{rolId}. | 422 Unprocessable Entity; exito = false; Mensaje: "No es posible eliminar el elemento: existen registros activos asociados. Desactívelo."; El elemento conserva sus datos. |

## Elementos comunes
### Sobre estándar de respuesta (todas las APIs)

Campos: `exito` (boolean), `mensaje` (string), `datos` (objeto, arreglo o `null`), `fechaHora` (ISO 8601 con zona horaria). El cuerpo no sustituye el código HTTP. Todas las APIs usan `Content-Type: application/json` en operaciones con body y `Authorization: Bearer <JWT>` (salvo registro, login y el webhook de la pasarela, que se autentica con su firma).
