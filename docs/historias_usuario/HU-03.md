# [HU-03] Administrar parámetros de proveedores, documentación legal y zonas de cobertura

**Dado:** Administrador autorizado.
**Para:** configurar tipos de proveedor, documentos requeridos y zonas de cobertura.
**Que:** definir qué proveedores pueden operar y en qué zonas pueden prestar servicios.

**Flujo esperado**
1. El administrador consulta los parámetros de proveedores, documentos y cobertura.
2. El sistema valida los permisos y los valores enviados.
3. Los cambios se guardan y se publican para MOD-03 y MOD-04.
4. Las validaciones documentales y búsquedas posteriores utilizan la configuración vigente.

**Criterios de aceptación**
- [ ] Los cambios solo pueden realizarlos usuarios autorizados.
- [ ] Los documentos requeridos deben estar asociados al tipo de proveedor correspondiente.
- [ ] Las zonas y radios de cobertura deben tener valores válidos (`radioKm` > 0).
- [ ] No se elimina una configuración con dependencias activas.
- [ ] Los talleres aliados se registran como tipo de proveedor `TALLER` con NIT único; solo los talleres habilitados se ofrecen para agendar citas (HU-23).

**Endpoint:** `GET /api/v1/parametros/tipos-proveedor` ; `POST /api/v1/parametros/tipos-proveedor` ; `PUT /api/v1/parametros/tipos-proveedor/{tipoProveedorId}` ; `DELETE /api/v1/parametros/tipos-proveedor/{tipoProveedorId}` ; `GET /api/v1/parametros/documentos-requeridos` ; `POST /api/v1/parametros/documentos-requeridos` ; `PUT /api/v1/parametros/documentos-requeridos/{documentoRequeridoId}` ; `DELETE /api/v1/parametros/documentos-requeridos/{documentoRequeridoId}` ; `GET /api/v1/parametros/zonas-cobertura` ; `POST /api/v1/parametros/zonas-cobertura` ; `PUT /api/v1/parametros/zonas-cobertura/{zonaId}` ; `DELETE /api/v1/parametros/zonas-cobertura/{zonaId}`

**Ejemplo de solicitud**
_POST /parametros/tipos-proveedor_
```json
{
  "codigo": "GRUA",
  "nombre": "Grúa"
}
```
_PUT /parametros/tipos-proveedor/{tipoProveedorId}_
```json
{
  "codigo": "GRUA",
  "nombre": "Grúa",
  "activo": true
}
```

**Respuesta exitosa**
```json
{
  "exito": true,
  "mensaje": "Catálogo de tipos de proveedor consultado exitosamente",
  "datos": [
    {
      "tipoProveedorId": "TP-01",
      "codigo": "GRUA",
      "nombre": "Grúa",
      "activo": true
    }
  ],
  "fechaHora": "2026-10-23T12:00:00-05:00"
}
```

**Notas técnicas:** `GET /api/v1/parametros/documentos-requeridos` figura en el documento base; las demás rutas son propuesta del equipo. Rutas, campos y mensajes son propuesta del equipo; se confirman en el Inventario de APIs (punto 4). La cobertura debe ser coherente con las reglas geoespaciales de MOD-04 (RN-04). Los talleres aliados se administran como un tipo de proveedor (decisión de integrar la antigua historia de talleres); falta decidir si requieren una entidad propia.

**Errores específicos de esta historia**

| Código | Cuándo ocurre | Mensaje (`mensaje`) |
|---|---|---|
| 422 Unprocessable Entity | Duplicado por `nombre` o eliminación de un elemento con dependencias activas (proveedores o búsquedas de MOD-03/MOD-04). | No es posible completar la operación: el elemento está duplicado o en uso |
| 422 Unprocessable Entity | Documento asociado a un tipo de proveedor inexistente o radio de cobertura no positivo. | Valor inválido en el campo indicado |

## Elementos comunes
### Sobre estándar de respuesta (todas las APIs)

Campos: `exito` (boolean), `mensaje` (string), `datos` (objeto, arreglo o `null`), `fechaHora` (ISO 8601 con zona horaria). El cuerpo no sustituye el código HTTP. Todas las APIs usan `Content-Type: application/json` en operaciones con body y `Authorization: Bearer <JWT>` (salvo registro, login y el webhook de la pasarela, que se autentica con su firma).
