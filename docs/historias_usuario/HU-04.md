# [HU-04] Registrar y actualizar vehículo

##  Historia de Usuario

**Dado:** Cliente autenticado.  
**Para:** registrar un vehículo y mantener sus datos actualizados.  
**Que:** solicitar auxilio y consultar la hoja de vida del vehículo correcto.

##  Flujo esperado

1. El cliente envía placa y atributos admitidos del vehículo.
2. El servicio valida formato y campos obligatorios.
3. Verifica que la placa no esté duplicada según las reglas del negocio.
4. Asocia el vehículo al usuario autenticado.
5. Devuelve el recurso creado o actualizado.

##  Criterios de aceptación

### 1. Estructura y lógica del servicio

- [ ] La placa es obligatoria y se normaliza según regla definida.
- [ ] No se duplica una placa registrada si la regla de unicidad así lo establece.
- [ ] Un usuario no modifica vehículos ajenos.
- [ ] Los campos obligatorios inválidos producen error de validación.
- [ ] El identificador del propietario proviene del token, no del body.

### 2. Estructura de la información y contrato JSON

Sobre estándar de respuesta para todas las APIs: `exito` (boolean), `mensaje` (string), `datos` (objeto o `null`) y `fechaHora` (ISO 8601 con zona horaria). El cuerpo no sustituye el código HTTP.

### Endpoint y método HTTP

- `POST /api/v1/vehiculos; PUT /api/v1/vehiculos/{vehiculoId}`
- `Content-Type: application/json` en operaciones con body.
- Autenticación: `Authorization: Bearer <JWT>` salvo registro/login.

### Ejemplo de solicitud

```json
{
  "placa": "ABC123",
  "marca": "Renault",
  "modelo": "Logan",
  "anio": 2021,
  "tipo": "AUTOMOVIL",
  "kilometraje": 45000
}
```

### Respuesta exitosa de referencia

```json
{
  "exito": true,
  "mensaje": "Vehículo registrado",
  "datos": {
    "id": "veh_789",
    "placa": "ABC123",
    "marca": "Renault",
    "modelo": "Logan",
    "anio": 2021,
    "kilometraje": 45000
  },
  "fechaHora": "2026-10-23T12:00:00-05:00"
}
```

##  Notas técnicas

Validar año razonable y kilometraje no negativo. La política de unicidad de placa debe coincidir con el modelo de datos.

##  Requisitos de pruebas

| Caso | Precondición | Acción exacta | Resultado esperado |
|---|---|---|---|
| Registro válido | JWT de cliente válido; placa no registrada. | POST /api/v1/vehiculos con payload válido. | 201 Created; devuelve id y placa normalizada. |
| Placa duplicada | Existe vehículo con placa ABC123. | POST /api/v1/vehiculos con la misma placa. | 409 Conflict; no crea duplicado. |
| Datos incompletos | JWT válido. | POST sin placa. | 422 Unprocessable Entity; indica campo requerido. |
| Actualización ajena | veh_789 pertenece a otro usuario. | PUT /api/v1/vehiculos/veh_789 con token ajeno. | 403 Forbidden o 404 según política; no modifica el vehículo. |
