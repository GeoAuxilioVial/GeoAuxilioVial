# [HU-06] Administrar esquemas tarifarios base y métodos de pago habilitados

**Dado:** Administrador autorizado.
**Para:** configurar las tarifas base y los métodos de pago habilitados.
**Que:** mantener actualizadas las condiciones económicas del servicio.

**Flujo esperado**
1. El administrador consulta las tarifas base y los métodos de pago.
2. El sistema valida permisos, valores monetarios y vigencia.
3. Los cambios válidos quedan guardados.
4. MOD-05 y MOD-07 consultan la configuración aplicable al cotizar y liquidar servicios.

**Criterios de aceptación**
- [ ] Solo usuarios autorizados pueden modificar tarifas y métodos de pago.
- [ ] Los valores monetarios deben ser numéricos y no negativos.
- [ ] La configuración vigente se identifica de forma inequívoca (`vigenteDesde`).
- [ ] No se elimina una tarifa referenciada por transacciones o servicios existentes.

**Endpoint:** `GET /api/v1/parametros/tarifario` ; `POST /api/v1/parametros/tarifario` ; `PUT /api/v1/parametros/tarifario/{tarifaId}` ; `DELETE /api/v1/parametros/tarifario/{tarifaId}` ; `GET /api/v1/parametros/metodos-pago` ; `POST /api/v1/parametros/metodos-pago` ; `PUT /api/v1/parametros/metodos-pago/{metodoPagoId}` ; `DELETE /api/v1/parametros/metodos-pago/{metodoPagoId}`

**Ejemplo de solicitud**
_POST /parametros/tarifario_
```json
{
  "tipoServicio": "GRUA",
  "valorBase": 85000.0,
  "valorPorKm": 3500.0,
  "moneda": "COP",
  "vigenteDesde": "2026-11-01"
}
```
_PUT /parametros/tarifario/{tarifaId}_
```json
{
  "tipoServicio": "GRUA",
  "valorBase": 85000.0,
  "valorPorKm": 3500.0,
  "moneda": "COP",
  "vigenteDesde": "2026-11-01",
  "activo": true
}
```

**Respuesta exitosa**
```json
{
  "exito": true,
  "mensaje": "Catálogo de tarifas base consultado exitosamente",
  "datos": [
    {
      "tarifaId": "TAR-01",
      "tipoServicio": "GRUA",
      "valorBase": 85000.0,
      "valorPorKm": 3500.0,
      "moneda": "COP",
      "vigenteDesde": "2026-11-01",
      "activo": true
    }
  ],
  "fechaHora": "2026-10-23T12:00:00-05:00"
}
```

**Notas técnicas:** `GET /api/v1/parametros/tarifario` figura en el documento base; las rutas de escritura y de métodos de pago son propuesta del equipo. Los campos `valorBase`, `valorPorKm` y `vigenteDesde` son propuesta; los factores exactos de la tarifa dinámica quedan por definir en la configuración tarifaria. Los cambios tarifarios no alteran retroactivamente servicios ya liquidados.

**Errores específicos de esta historia**

| Código | Cuándo ocurre | Mensaje (`mensaje`) |
|---|---|---|
| 422 Unprocessable Entity | Duplicado por `tipoServicio` o eliminación de un elemento con dependencias activas (transacciones o servicios existentes). | No es posible completar la operación: el elemento está duplicado o en uso |
| 422 Unprocessable Entity | Valor monetario negativo o no numérico. | Valor monetario inválido en el campo indicado |

**Requisitos de pruebas**

| Caso | Precondición | Acción exacta | Resultado esperado |
|---|---|---|---|

| Usuario sin permisos administrativos | Usuario autenticado con rol CLIENTE. | POST /api/v1/parametros/tarifario con el cuerpo de ejemplo. | 403 Forbidden; exito = false; Mensaje: "Acceso denegado: se requieren permisos de Administrador".; No se modifica ningún dato. |

| Actualización válida disponible para los módulos consumidores | Tarifa TAR-01 vigente. | PUT /api/v1/parametros/tarifario/TAR-01 con valorBase = 90000 y luego GET /api/v1/parametros/tarifario. | 200 OK; datos muestra el nuevo valor vigente.; Los servicios ya liquidados no cambian (sin efecto retroactivo). |

## Elementos comunes
### Sobre estándar de respuesta (todas las APIs)

Campos: `exito` (boolean), `mensaje` (string), `datos` (objeto, arreglo o `null`), `fechaHora` (ISO 8601 con zona horaria). El cuerpo no sustituye el código HTTP. Todas las APIs usan `Content-Type: application/json` en operaciones con body y `Authorization: Bearer <JWT>` (salvo registro, login y el webhook de la pasarela, que se autentica con su firma).
