# [HU-07] Validar proveedor y sus documentos

## Historia de Usuario

**Dado:** Proveedor y revisor autorizado.  
**Para:** registrar documentos y conocer su estado de validación.  
**Que:** habilitar proveedores únicamente cuando cumplan los requisitos definidos.

## Flujo esperado

1. El proveedor carga metadatos y referencia segura del documento.
2. El sistema valida tipo, tamaño y vigencia declarada.
3. La solicitud queda PENDIENTE_REVISION.
4. Un revisor autorizado aprueba o rechaza indicando motivo.
5. La habilitación se recalcula considerando todos los documentos obligatorios.

## Criterios de aceptación

### 1. Estructura y lógica del servicio

- [ ] No se habilita proveedor con documentos obligatorios pendientes, rechazados o vencidos.
- [ ] Solo revisores autorizados pueden aprobar o rechazar.
- [ ] Toda decisión guarda revisor, fecha y motivo.
- [ ] El archivo no se expone públicamente por URL abierta.
- [ ] La respuesta no revela contenido documental a usuarios no autorizados.

### 2. Estructura de la información y contrato JSON

Sobre estándar de respuesta para todas las APIs: `exito` (boolean), `mensaje` (string), `datos` (objeto o `null`) y `fechaHora` (ISO 8601 con zona horaria). El cuerpo no sustituye el código HTTP.

### Endpoint y método HTTP

- `POST /api/v1/proveedores/documentos; PATCH /api/v1/backoffice/proveedores/{proveedorId}/documentos/{documentoId}`
- `Content-Type: application/json` en operaciones con body.
- Autenticación: `Authorization: Bearer <JWT>` salvo registro/login.

### Ejemplo de solicitud

```json
{
  "carga": {
    "tipoDocumento": "IDENTIFICACION",
    "archivoId": "file_123",
    "fechaVencimiento": "2027-10-23"
  },
  "decision": {
    "decision": "APROBADO",
    "motivo": "Documento legible y vigente"
  }
}
```

### Respuesta exitosa de referencia

```json
{
  "exito": true,
  "mensaje": "Documento recibido para revisión",
  "datos": {
    "documentoId": "doc_123",
    "estado": "PENDIENTE_REVISION"
  },
  "fechaHora": "2026-10-23T12:00:00-05:00"
}
```

## 🔧 Notas técnicas

Validar almacenamiento de archivos fuera del directorio público, antivirus si aplica, permisos mínimos y auditoría. Definir si la carga usa multipart/form-data o carga firmada.

## Requisitos de pruebas

| Caso | Precondición | Acción exacta | Resultado esperado |
|---|---|---|---|
| Carga válida | JWT de proveedor autenticado; proveedor asociado al token. | POST /api/v1/proveedores/documentos con metadatos válidos. | 201 Created; estado PENDIENTE_REVISION. |
| Revisión por autorizado | Usuario con rol REVISOR; documento pendiente. | PATCH /api/v1/backoffice/proveedores/prov_1/documentos/doc_123 con decision APROBADO. | 200 OK; decisión y auditoría quedan persistidas. |
| Sin rol revisor | JWT de cliente sin permiso administrativo. | PATCH al endpoint de revisión. | 403 Forbidden; estado no cambia. |
| Documento vencido | Documento obligatorio con fecha de vencimiento anterior a hoy. | Solicitar habilitación o registrar revisión. | 422 o estado de proveedor no habilitado; no queda disponible. |
