# [HU-07] Administrar criterios de evaluación del servicio y escalas de reputación ponderada

**Dado:** Administrador autorizado.
**Para:** mantener los criterios de evaluación del servicio y las escalas de reputación.
**Que:** parametrizar la calificación y el cálculo de reputación del proveedor sin modificar el código fuente y sin acoplar MOD-08 a la configuración de pagos.

**Flujo esperado**
1. El administrador consulta los criterios de evaluación y las escalas de reputación vigentes.
2. El sistema valida permisos y los valores enviados (pesos, mínimo y máximo de la escala).
3. Los cambios válidos se guardan en la parametrización (MOD-09, submódulo de evaluación y reputación).
4. MOD-08 consulta la configuración vigente al registrar calificaciones y calcular la reputación.

**Criterios de aceptación**
- [ ] Solo administradores autorizados pueden modificar criterios y escalas.
- [ ] Cada criterio tiene identificador, nombre y peso válidos; la escala cumple `minimo` < `maximo`.
- [ ] Los cambios válidos quedan disponibles para HU-27 y HU-28 sin alterar calificaciones ya registradas.
- [ ] No se elimina un criterio o escala utilizados por calificaciones o índices existentes; se desactiva.

**Endpoint:** `GET /api/v1/parametros/criterios-evaluacion` ; `POST /api/v1/parametros/criterios-evaluacion` ; `PUT /api/v1/parametros/criterios-evaluacion/{criterioId}` ; `DELETE /api/v1/parametros/criterios-evaluacion/{criterioId}` ; `GET /api/v1/parametros/escalas-reputacion` ; `POST /api/v1/parametros/escalas-reputacion` ; `PUT /api/v1/parametros/escalas-reputacion/{escalaId}` ; `DELETE /api/v1/parametros/escalas-reputacion/{escalaId}`

**Ejemplo de solicitud**
_POST /parametros/criterios-evaluacion_
```json
{
  "nombre": "Puntualidad",
  "peso": 0.3
}
```
_PUT /parametros/criterios-evaluacion/{criterioId}_
```json
{
  "nombre": "Puntualidad",
  "peso": 0.3,
  "activo": true
}
```

**Respuesta exitosa**
```json
{
  "exito": true,
  "mensaje": "Catálogo de criterios de evaluación consultado exitosamente",
  "datos": [
    {
      "criterioId": "CE-01",
      "nombre": "Puntualidad",
      "peso": 0.3,
      "activo": true
    }
  ],
  "fechaHora": "2026-10-23T12:00:00-05:00"
}
```

**Notas técnicas:** Rutas, campos y mensajes son propuesta del equipo; se confirman en el Inventario de APIs (punto 4). FUN-28 se cubre con esta historia (CA-03). La fórmula de ponderación del índice (RN-P14) sigue por definir; esta historia solo parametriza criterios, pesos y escalas. La regla «los pesos de los criterios activos suman 1» es propuesta del equipo y debe confirmarse. Historia nueva de la v6: su redacción es borrador del equipo y debe aprobarse.

**Errores específicos de esta historia**

| Código | Cuándo ocurre | Mensaje (`mensaje`) |
|---|---|---|
| 422 Unprocessable Entity | Duplicado por `nombre` o eliminación de un elemento con dependencias activas (calificaciones o índices de reputación ya calculados). | No es posible completar la operación: el elemento está duplicado o en uso |
| 422 Unprocessable Entity | Escala con `minimo` mayor o igual que `maximo`, o peso fuera de rango. | Valor inválido en el campo indicado |

Campos: `exito` (boolean), `mensaje` (string), `datos` (objeto, arreglo o `null`), `fechaHora` (ISO 8601 con zona horaria). El cuerpo no sustituye el código HTTP.
