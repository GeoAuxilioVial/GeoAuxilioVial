# [HU-12] Actualizar el estado operativo del vehículo a "varado" ante un reporte de falla

**Dado:** Cliente propietario de un vehículo.
**Para:** reportar una avería que impide continuar el viaje.
**Que:** marcar el vehículo como varado e iniciar el flujo de auxilio vial.

**Flujo esperado**
1. El cliente reporta la avería y selecciona el vehículo afectado.
2. El backend verifica propiedad, estado activo y ausencia de otra solicitud abierta.
3. El sistema actualiza el estado operativo a `VARADO`.
4. Se confirma el cambio y se habilita el proceso de solicitud de auxilio (HU-19).

**Criterios de aceptación**
- [ ] No se aceptan reportes de vehículos inactivos o ajenos al usuario.
- [ ] No se duplica el reporte si existe una solicitud abierta para el vehículo.
- [ ] Un reporte válido cambia el estado a `VARADO`.
- [ ] El sistema solo confirma la operación cuando el cambio se ha persistido.

**Endpoint:** `PUT /api/v1/vehiculos/{vehiculoId}/estado-operativo`

**Ejemplo de solicitud**
```json
{
  "estadoOperativo": "VARADO",
  "tipoAveriaId": "AV-01",
  "descripcion": "El vehículo no enciende"
}
```

**Respuesta exitosa**
```json
{
  "exito": true,
  "mensaje": "Estado operativo actualizado a VARADO",
  "datos": {
    "vehiculoId": "VEH-0001",
    "estadoOperativo": "VARADO",
    "actualizadoEn": "2026-10-23T10:30:00"
  },
  "fechaHora": "2026-10-23T12:00:00-05:00"
}
```

**Notas técnicas:** El endpoint de escritura del estado está pendiente en el diseño (CI-01 solo lectura); la ruta es propuesta del equipo. Rutas, campos y mensajes son propuesta del equipo; se confirman en el Inventario de APIs (punto 4). La transición de estado debe respetar el ciclo de vida del vehículo y del auxilio.

**Errores específicos de esta historia**

| Código | Cuándo ocurre | Mensaje (`mensaje`) |
|---|---|---|
| 409 Conflict | Ya existe una solicitud abierta para el vehículo. | Ya existe una solicitud abierta para este vehículo |
| 422 Unprocessable Entity | El vehículo está inactivo o la transición no respeta el ciclo de vida. | El vehículo no está activo |

**Requisitos de pruebas**

| Caso | Precondición | Acción exacta | Resultado esperado |
|---|---|---|---|
| Vehículo activo sin solicitud abierta | Cliente propietario; vehículo ACTIVO; sin solicitud abierta. | PUT /api/v1/vehiculos/VEH-0001/estado-operativo con estadoOperativo = VARADO. | 200 OK; exito = true; datos.estadoOperativo = VARADO y persistido. |
| Vehículo inactivo | El vehículo está INACTIVO. | PUT /api/v1/vehiculos/VEH-0002/estado-operativo. | 422 Unprocessable Entity; exito = false; Mensaje: "El vehículo no está activo".; El estado no cambia. |
| Solicitud abierta existente | Existe una solicitud abierta para el vehículo. | PUT /api/v1/vehiculos/VEH-0001/estado-operativo. | 409 Conflict; exito = false; Mensaje: "Ya existe una solicitud abierta para este vehículo".; No se duplica el flujo. |
| Vehículo ajeno | El vehículo pertenece a otro usuario. | PUT /api/v1/vehiculos/VEH-0500/estado-operativo. | 403 Forbidden; exito = false; No se modifica el vehículo. |
| Fallo de persistencia | Falla simulada al guardar el estado. | PUT /api/v1/vehiculos/VEH-0001/estado-operativo. | 500 Internal Server Error; exito = false; No se confirma un cambio que no se guardó; el estado sigue ACTIVO. |

**Trazabilidad:** `MOD-02`, `FUN-05`, `PRO-05`
