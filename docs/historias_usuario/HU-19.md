# [HU-19] Calcular y presentar cotización estimada del auxilio en tiempo real

**Dado:** Cliente autenticado con vehículo registrado.
**Para:** obtener una cotización estimada y crear la solicitud de auxilio con vehículo, ubicación y tipo de avería.
**Que:** conocer el valor estimado con el tarifario vigente e iniciar el proceso de asistencia vial.

**Flujo esperado**
1. El cliente envía tipo de avería, vehículo, ubicación y servicio requerido.
2. El backend valida datos y autorización sobre el vehículo.
3. Consulta tarifario vigente de MOD-09/SUB-27.
4. Calcula el valor con reglas activas y devuelve desglose y vigencia de cotización.
5. No crea una solicitud confirmada hasta que el usuario ejecute el flujo de creación.
6. Con la cotización a la vista, el cliente confirma y envía vehículo, avería, descripción y ubicación para crear la solicitud.
7. El backend valida token, propiedad del vehículo y datos obligatorios.
8. Se registra la solicitud en el estado inicial definido por la máquina de estados.
9. Se dispara el proceso de búsqueda/asignación sin duplicar la solicitud.
10. Se devuelve el identificador y el estado inicial.

**Criterios de aceptación**
- [ ] Se usa el tarifario vigente en el momento de cotizar.
- [ ] El importe no es negativo y la moneda se identifica.
- [ ] Datos obligatorios ausentes o inválidos producen 422.
- [ ] El usuario solo cotiza para vehículos autorizados.
- [ ] La cotización no se presenta como pago confirmado.
- [ ] El vehículo debe pertenecer al cliente o estar autorizado.
- [ ] La ubicación debe contener coordenadas válidas.
- [ ] La solicitud se crea en un estado inicial permitido, por ejemplo PENDIENTE_ASIGNACION.
- [ ] Reintentos no deben crear duplicados si se utiliza Idempotency-Key.
- [ ] No se considera proveedor asignado hasta persistir una asignación válida.

**Endpoint:** `POST /api/v1/auxilio/cotizaciones` ; `POST /api/v1/auxilio/solicitudes`

**Ejemplo de solicitud**
_Cotización_
```json
{
  "vehiculoId": "veh_789",
  "tipoAveria": "BATERIA",
  "ubicacion": {
    "latitud": 7.1193,
    "longitud": -73.1227
  },
  "servicio": "ASISTENCIA_BATERIA"
}
```
_Crear solicitud_
```json
{
  "vehiculoId": "veh_789",
  "tipoAveria": "LLANTA",
  "descripcion": "Pinchazo en vía urbana",
  "ubicacion": {
    "latitud": 7.1193,
    "longitud": -73.1227
  }
}
```

**Respuesta exitosa**
_Cotización_
```json
{
  "exito": true,
  "mensaje": "Cotización calculada",
  "datos": {
    "cotizacionId": "cot_101",
    "moneda": "COP",
    "subtotal": 85000,
    "impuestos": 0,
    "total": 85000,
    "tarifarioVersion": "2026-10",
    "vigenteHasta": "2026-10-23T13:00:00-05:00"
  },
  "fechaHora": "2026-10-23T12:00:00-05:00"
}
```
_Crear solicitud_
```json
{
  "exito": true,
  "mensaje": "Solicitud de auxilio creada",
  "datos": {
    "solicitudId": "aux_456",
    "estado": "PENDIENTE_ASIGNACION",
    "vehiculoId": "veh_789",
    "creadaEn": "2026-10-23T12:00:00-05:00"
  },
  "fechaHora": "2026-10-23T12:00:00-05:00"
}
```

**Notas técnicas:** la fórmula de cotización debe ser consistente con la regla de negocio y con la configuración de SUB-27. El total del ejemplo es ilustrativo. la máquina de estados es la fuente de verdad; crear, aceptar/rechazar, expirar, cancelar y cerrar son transiciones del flujo de auxilio.

**Requisitos de pruebas**

| Caso | Precondición | Acción exacta | Resultado esperado |
|---|---|---|---|
| Cotización válida | JWT válido; vehículo pertenece al usuario; tarifario activo. | POST /api/v1/auxilio/cotizaciones con payload completo. | 200 OK; total numérico no negativo y moneda COP. |
| Falta tipo de avería | JWT válido; vehículo propio. | POST sin tipoAveria. | 422 Unprocessable Entity; no devuelve cotización exitosa. |
| Vehículo ajeno | JWT válido de otro usuario. | POST con vehiculoId ajeno. | 403 Forbidden o 404 según política. |
| Tarifario no disponible | Tarifario no tiene versión activa. | POST con datos válidos. | 500 Internal Server Error controlado o 503 Service Unavailable si se adopta; no devuelve total ficticio. |
| Solicitud válida | JWT cliente; vehículo propio activo. | POST /api/v1/auxilio/solicitudes con payload completo. | 201 Created; estado inicial válido y solicitudId presente. |
| Vehículo ajeno | JWT válido; vehículo pertenece a otro usuario. | POST con vehiculoId ajeno. | 403 Forbidden o 404; no crea solicitud. |
| Ubicación inválida | JWT válido; latitud=200. | POST con ubicación inválida. | 422 Unprocessable Entity; no se crea solicitud. |
| Reintento idempotente | Se envió una solicitud previamente con Idempotency-Key K1. | Repetir POST con la misma clave y mismo payload. | Devuelve el mismo recurso/identificador sin duplicar solicitud. |

**Trazabilidad:** `MOD-05`, `FUN-12`, `PRO-12`

## Elementos comunes
### Sobre estándar de respuesta (todas las APIs)

Campos: `exito` (boolean), `mensaje` (string), `datos` (objeto, arreglo o `null`), `fechaHora` (ISO 8601 con zona horaria). El cuerpo no sustituye el código HTTP. Todas las APIs usan `Content-Type: application/json` en operaciones con body y `Authorization: Bearer <JWT>` (salvo registro, login y el webhook de la pasarela, que se autentica con su firma).
