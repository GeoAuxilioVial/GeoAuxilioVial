# [HU-25] Registrar el mantenimiento preventivo ejecutado y actualizar la hoja de vida vehicular

**Dado:** Taller aliado o usuario autorizado.
**Para:** registrar los trabajos de mantenimiento realizados.
**Que:** mantener actualizado el historial técnico y el kilometraje del vehículo.

**Flujo esperado**
1. El actor autorizado registra el mantenimiento ejecutado, fecha, actividades y kilometraje.
2. El sistema valida la autorización y los datos obligatorios.
3. El mantenimiento se guarda asociado al vehículo y, cuando corresponda, al taller.
4. La hoja de vida vehicular se actualiza para futuras consultas y alertas.

**Criterios de aceptación**
- [ ] El registro requiere los campos obligatorios definidos para el mantenimiento.
- [ ] El usuario solo puede registrar o modificar mantenimientos para los que tiene autorización.
- [ ] El kilometraje registrado debe cumplir las validaciones del sistema.
- [ ] El mantenimiento aparece en la consulta posterior del historial (HU-13).

**Endpoint:** `POST /api/v1/mantenimiento/registros`

**Ejemplo de solicitud**
```json
{
  "vehiculoId": "VEH-0001",
  "tallerId": "TAL-001",
  "fecha": "2026-11-05",
  "actividades": [
    "Cambio de aceite",
    "Revisión de frenos"
  ],
  "kilometraje": 50000
}
```

**Respuesta exitosa**
```json
{
  "exito": true,
  "mensaje": "Mantenimiento registrado exitosamente",
  "datos": {
    "registroId": "MNT-0001",
    "vehiculoId": "VEH-0001",
    "kilometrajeActualizado": 50000
  },
  "fechaHora": "2026-10-23T12:00:00-05:00"
}
```

**Notas técnicas:** El endpoint de registro de mantenimiento está pendiente en el diseño; la ruta y los campos definitivos se acuerdan en el contrato (propuesta del equipo). Rutas, campos y mensajes son propuesta del equipo; se confirman en el Inventario de APIs (punto 4). CI-13 registra el cobro cuando aplica; no se modifica aquí.

**Errores específicos de esta historia**

| Código | Cuándo ocurre | Mensaje (`mensaje`) |
|---|---|---|
| 422 Unprocessable Entity | Kilometraje incoherente con las lecturas previas. | El kilometraje es menor al último registrado |

**Requisitos de pruebas**

| Caso | Precondición | Acción exacta | Resultado esperado |
|---|---|---|---|
| Datos válidos | Actor autorizado sobre el vehículo. | POST /api/v1/mantenimiento/registros con el cuerpo de ejemplo. | 201 Created; exito = true; datos.registroId generado. |
| Datos incompletos | Actor autorizado. | POST /api/v1/mantenimiento/registros sin actividades. | 422 Unprocessable Entity; exito = false; El mensaje identifica el campo actividades. |
| Vehículo no autorizado | El actor no tiene relación con el vehículo. | POST /api/v1/mantenimiento/registros con vehiculoId = VEH-0500. | 403 Forbidden; exito = false; La operación se deniega sin crear el registro. |
| Kilometraje menor al último registrado | La última lectura es 50000. | POST /api/v1/mantenimiento/registros con kilometraje = 40000. | 422 Unprocessable Entity; exito = false; Mensaje: "El kilometraje es menor al último registrado". |
| Consulta posterior del historial | Mantenimiento MNT-0001 registrado. | GET /api/v1/vehiculos/VEH-0001/historial. | 200 OK; datos.eventos incluye el mantenimiento registrado. |

**Trazabilidad:** `MOD-06`, `FUN-18`, `PRO-18`

## Elementos comunes
### Sobre estándar de respuesta (todas las APIs)

Campos: `exito` (boolean), `mensaje` (string), `datos` (objeto, arreglo o `null`), `fechaHora` (ISO 8601 con zona horaria). El cuerpo no sustituye el código HTTP. Todas las APIs usan `Content-Type: application/json` en operaciones con body y `Authorization: Bearer <JWT>` (salvo registro, login y el webhook de la pasarela, que se autentica con su firma).
