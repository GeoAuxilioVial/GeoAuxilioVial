# [HU-12] Crear solicitud de auxilio vial

## Historia de Usuario

**Dado:** Cliente autenticado con vehículo registrado.  
**Para:** crear una solicitud con vehículo, ubicación y tipo de avería.  
**Que:** iniciar el proceso de asistencia vial.
## Flujo esperado

1. El cliente envía vehículo, avería, descripción y ubicación.
2. El backend valida token, propiedad del vehículo y datos obligatorios.
3. Se registra la solicitud en estado inicial definido por la máquina de estados.
4. Se dispara el proceso de búsqueda/asignación sin duplicar la solicitud.
5. Se devuelve el identificador y estado inicial.

## Criterios de aceptación

### 1. Estructura y lógica del servicio

- [ ] El vehículo debe pertenecer al cliente o estar autorizado.
- [ ] La ubicación debe contener coordenadas válidas.
- [ ] La solicitud se crea en un estado inicial permitido, por ejemplo PENDIENTE_ASIGNACION.
- [ ] Reintentos no deben crear duplicados si se utiliza Idempotency-Key.
- [ ] No se considera proveedor asignado hasta persistir una asignación válida.

### 2. Estructura de la información y contrato JSON

Sobre estándar de respuesta para todas las APIs: `exito` (boolean), `mensaje` (string), `datos` (objeto o `null`) y `fechaHora` (ISO 8601 con zona horaria). El cuerpo no sustituye el código HTTP.

### Endpoint y método HTTP

- `POST /api/v1/auxilio/solicitudes`
- `Content-Type: application/json` en operaciones con body.
- Autenticación: `Authorization: Bearer <JWT>` salvo registro/login.

### Ejemplo de solicitud

```json
{
  "vehiculoId": "veh_789",
  "tipoAveria": "LLANTA",
  "descripcion": "Pinchazo en vía urbana",
  "ubicacion": {
    "latitud": 7.1193,
    "longitud": -73.1227
  }
}
```

### Respuesta exitosa de referencia

```json
{
  "exito": true,
  "mensaje": "Solicitud de auxilio creada",
  "datos": {
    "solicitudId": "aux_456",
    "estado": "PENDIENTE_ASIGNACION",
    "vehiculoId": "veh_789",
    "creadaEn": "2026-10-23T12:00:00-05:00"
  },
  "fechaHora": "2026-10-23T12:00:00-05:00"
}
```

## Notas técnicas

La máquina de estados es la fuente de verdad; crear, aceptar/rechazar, expirar, cancelar y cerrar son transiciones del flujo de auxilio, no historias complementarias independientes si la descomposición no las define.

## Requisitos de pruebas

| Caso | Precondición | Acción exacta | Resultado esperado |
|---|---|---|---|
| Solicitud válida | JWT cliente; vehículo propio activo. | POST /api/v1/auxilio/solicitudes con payload completo. | 201 Created; estado inicial válido y solicitudId presente. |
| Vehículo ajeno | JWT válido; vehículo pertenece a otro usuario. | POST con vehiculoId ajeno. | 403 Forbidden o 404; no crea solicitud. |
| Ubicación inválida | JWT válido; latitud=200. | POST con ubicación inválida. | 422 Unprocessable Entity; no se crea solicitud. |
| Reintento idempotente | Se envió una solicitud previamente con Idempotency-Key K1. | Repetir POST con la misma clave y mismo payload. | Devuelve el mismo recurso/identificador sin duplicar solicitud. |
