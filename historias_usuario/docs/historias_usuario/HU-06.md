# [HU-06] Cotizar una solicitud de auxilio vial

## Historia de Usuario

**Dado:** Cliente autenticado.  
**Para:** obtener una cotización antes de confirmar el auxilio.  
**Que:** conocer el valor estimado con base en el tarifario vigente.

## Flujo esperado

1. El cliente envía tipo de avería, vehículo, ubicación y servicio requerido.
2. El backend valida datos y autorización sobre el vehículo.
3. Consulta tarifario vigente de MOD-09/SUB-27.
4. Calcula el valor con reglas activas y devuelve desglose y vigencia de cotización.
5. No crea una solicitud confirmada hasta que el usuario ejecute el flujo de creación.

## Criterios de aceptación

### 1. Estructura y lógica del servicio

- [ ] Se usa el tarifario vigente en el momento de cotizar.
- [ ] El importe no es negativo y la moneda se identifica.
- [ ] Datos obligatorios ausentes o inválidos producen 422.
- [ ] El usuario solo cotiza para vehículos autorizados.
- [ ] La cotización no se presenta como pago confirmado.

### 2. Estructura de la información y contrato JSON

Sobre estándar de respuesta para todas las APIs: `exito` (boolean), `mensaje` (string), `datos` (objeto o `null`) y `fechaHora` (ISO 8601 con zona horaria). El cuerpo no sustituye el código HTTP.

### Endpoint y método HTTP

- `POST /api/v1/auxilio/cotizaciones`
- `Content-Type: application/json` en operaciones con body.
- Autenticación: `Authorization: Bearer <JWT>` salvo registro/login.

### Ejemplo de solicitud

```json
{
  "vehiculoId": "veh_789",
  "tipoAveria": "BATERIA",
  "ubicacion": {
    "latitud": 7.1193,
    "longitud": -73.1227
  },
  "servicio": "ASISTENCIA_BATERIA"
}
```

## Notas técnicas

La fórmula de cotización debe ser consistente con la regla de negocio y con la configuración de SUB-27. El total del ejemplo es ilustrativo.

## Requisitos de pruebas

| Caso | Precondición | Acción exacta | Resultado esperado |
|---|---|---|---|
| Cotización válida | JWT válido; vehículo pertenece al usuario; tarifario activo. | POST /api/v1/auxilio/cotizaciones con payload completo. | 200 OK; total numérico no negativo y moneda COP. |
| Falta tipo de avería | JWT válido; vehículo propio. | POST sin tipoAveria. | 422 Unprocessable Entity; no devuelve cotización exitosa. |
| Vehículo ajeno | JWT válido de otro usuario. | POST con vehiculoId ajeno. | 403 Forbidden o 404 según política. |
| Tarifario no disponible | Tarifario no tiene versión activa. | POST con datos válidos. | 500 Internal Server Error controlado o 503 Service Unavailable si se adopta; no devuelve total ficticio. |
