# [HU-08] Gestionar disponibilidad del proveedor

## Historia de Usuario

**Dado:** Proveedor habilitado.  
**Para:** activar o desactivar mi disponibilidad operativa.  
**Que:** recibir asignaciones solo cuando puedo atender y cumplo los requisitos.

## Flujo esperado

1. El proveedor autenticado envía el estado deseado.
2. El servicio valida identidad, rol, habilitación y documentos vigentes.
3. Persiste el cambio y registra fecha de actualización.
4. La búsqueda geográfica consume la disponibilidad vigente.
5. Devuelve el estado resultante.

## Criterios de aceptación

### 1. Estructura y lógica del servicio

- [ ] Solo proveedor habilitado puede activar disponibilidad.
- [ ] Documentos pendientes, rechazados o vencidos bloquean el estado DISPONIBLE.
- [ ] Estado actualizado se refleja en búsquedas posteriores.
- [ ] Valores de estado fuera del catálogo se rechazan.
- [ ] El sistema no confirma un cambio si la persistencia falla.

### 2. Estructura de la información y contrato JSON

Sobre estándar de respuesta para todas las APIs: `exito` (boolean), `mensaje` (string), `datos` (objeto o `null`) y `fechaHora` (ISO 8601 con zona horaria). El cuerpo no sustituye el código HTTP.

### Endpoint y método HTTP

- `PATCH /api/v1/proveedores/me/disponibilidad`
- `Content-Type: application/json` en operaciones con body.
- Autenticación: `Authorization: Bearer <JWT>` salvo registro/login.

### Ejemplo de solicitud

```json
{
  "disponible": true
}
```

### Respuesta exitosa de referencia

```json
{
  "exito": true,
  "mensaje": "Disponibilidad actualizada",
  "datos": {
    "proveedorId": "prov_123",
    "disponible": true,
    "actualizadoEn": "2026-10-23T12:00:00-05:00"
  },
  "fechaHora": "2026-10-23T12:00:00-05:00"
}
```

## Notas técnicas

El proveedor se determina desde el token, no desde un proveedorId recibido por body. Considerar consistencia entre persistencia y caché/búsqueda geográfica.

## Requisitos de pruebas

| Caso | Precondición | Acción exacta | Resultado esperado |
|---|---|---|---|
| Activación válida | JWT proveedor habilitado; documentos vigentes. | PATCH /api/v1/proveedores/me/disponibilidad con disponible=true. | 200 OK; disponible=true. |
| Documentos vencidos | Proveedor tiene documento obligatorio vencido. | PATCH con disponible=true. | 422 Unprocessable Entity; permanece no disponible. |
| Estado inválido | JWT válido de proveedor. | PATCH con disponible="tal_vez". | 422 Unprocessable Entity. |
| Usuario no proveedor | JWT con rol CLIENTE solamente. | PATCH al endpoint. | 403 Forbidden; no cambia disponibilidad. |
