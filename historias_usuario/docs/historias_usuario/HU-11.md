# [HU-11] Actualizar ubicación del proveedor

## Historia de Usuario

**Dado:** Proveedor autenticado y habilitado.  
**Para:** actualizar mi ubicación operativa durante la jornada.  
**Que:** permitir que las búsquedas de auxilio utilicen una posición reciente y confiable.

## Flujo esperado

1. El cliente del proveedor envía coordenadas y precisión opcional.
2. El backend valida JWT, rol, disponibilidad y rangos de coordenadas.
3. Se registra la ubicación con marca temporal generada por servidor.
4. El sistema aplica la política de retención y frescura definida.
5. Las búsquedas de proveedores cercanos consumen la ubicación vigente.

## Criterios de aceptación

### 1. Estructura y lógica del servicio

- [ ] Latitud está entre -90 y 90 y longitud entre -180 y 180.
- [ ] El proveedor solo actualiza su propia ubicación.
- [ ] La fechaHora de registro la determina el servidor.
- [ ] Ubicaciones antiguas no se consideran vigentes para asignaciones.
- [ ] Si el proveedor no está autorizado o habilitado, la actualización se rechaza.

### 2. Estructura de la información y contrato JSON

Sobre estándar: `exito` (boolean), `mensaje` (string), `datos` (objeto o `null`) y `fechaHora` (ISO 8601 con zona horaria). El código HTTP es parte del contrato.

### Endpoint y método HTTP

- `PUT /api/v1/proveedores/me/ubicacion`
- `Content-Type: application/json` cuando exista body.
- Autenticación: `Authorization: Bearer <JWT>`.

### Ejemplo de solicitud

```json
{
  "latitud": 7.1193,
  "longitud": -73.1227,
  "precisionMetros": 20
}
```

### Respuesta exitosa de referencia

```json
{
  "exito": true,
  "mensaje": "Ubicación actualizada",
  "datos": {
    "proveedorId": "prov_123",
    "latitud": 7.1193,
    "longitud": -73.1227,
    "precisionMetros": 20,
    "actualizadaEn": "2026-10-23T12:00:00-05:00"

  "fechaHora": "2026-10-23T12:00:00-05:00"
}
```

## Notas técnicas

Proteger la ubicación como dato sensible: limitar acceso, retención y exposición al mínimo necesario. El servidor debe generar la marca temporal; no confiar en timestamps del dispositivo.

## Requisitos de pruebas

| Caso | Precondición | Acción exacta | Resultado esperado |
|---|---|---|---|
| Coordenadas válidas | JWT de proveedor habilitado. | PUT /api/v1/proveedores/me/ubicacion con latitud y longitud válidas. | 200 OK; ubicación actualizada con timestamp de servidor. |
| Latitud fuera de rango | JWT válido. | PUT con latitud=95. | 422 Unprocessable Entity; ubicación previa se conserva. |
| Usuario cliente | JWT con rol CLIENTE, sin rol proveedor. | PUT al endpoint. | 403 Forbidden; no registra ubicación. |
| Búsqueda posterior | Ubicación actualizada y dentro del umbral de frescura. | GET /api/v1/proveedores/cercanos con coordenadas y radio válidos. | 200 OK; el proveedor puede aparecer si cumple disponibilidad, cobertura y tipo de servicio. |
