# [HU-15] Cerrar servicio y solicitar liberación del pago

## Historia de Usuario

**Dado:** Cliente y proveedor participantes del servicio.  
**Para:** confirmar la finalización del auxilio.  
**Que:** cerrar la solicitud y habilitar la gestión de pago conforme a las reglas del sistema.

## Flujo esperado

1. El proveedor registra que el trabajo terminó.
2. El cliente confirma la finalización o se cumple el plazo de confirmación configurado.
3. El servicio valida el estado actual y la regla aplicable.
4. Se registra el cierre y se solicita a MOD-07 la liberación/captura del pago.
5. El estado financiero solo cambia cuando MOD-07 confirma la operación correspondiente.

## Criterios de aceptación

### 1. Estructura y lógica del servicio

- [ ] Solo se cierra una solicitud en un estado que admita finalización.
- [ ] La confirmación y el vencimiento del plazo se tratan conforme a la regla configurada.
- [ ] El cierre operativo y el pago se registran como estados separados.
- [ ] No se informa pago exitoso sin confirmación de MOD-07/proveedor de pagos.
- [ ] Se conserva auditoría del cierre.

### 2. Estructura de la información y contrato JSON

Sobre estándar de respuesta para todas las APIs: `exito` (boolean), `mensaje` (string), `datos` (objeto o `null`) y `fechaHora` (ISO 8601 con zona horaria). El cuerpo no sustituye el código HTTP.

### Endpoint y método HTTP

- `POST /api/v1/auxilio/solicitudes/{solicitudId}/cierre`
- `Content-Type: application/json` en operaciones con body.
- Autenticación: `Authorization: Bearer <JWT>` salvo registro/login.

### Ejemplo de solicitud

```json
{
  "confirmacionCliente": true,
  "observacion": "Servicio recibido correctamente"
}
```

## Notas técnicas

MOD-05 mantiene el ciclo operativo; MOD-07 es responsable del ciclo financiero. Usar eventos/outbox o mecanismo de reintento para evitar pérdida de solicitud de pago.

## Requisitos de pruebas

| Caso | Precondición | Acción exacta | Resultado esperado |
|---|---|---|---|
| Cierre confirmado | Servicio en estado permitido; token del cliente participante. | POST /api/v1/auxilio/solicitudes/aux_456/cierre con confirmacionCliente=true. | 200 OK; estadoServicio=COMPLETADO y pago no se marca exitoso antes de confirmación. |
| Estado no cerrable | Solicitud aún sin aceptación del proveedor. | POST al endpoint de cierre. | 422 Unprocessable Entity; no cambia el estado. |
| Usuario ajeno | JWT de cliente no participante. | POST al endpoint de cierre. | 403 Forbidden o 404; no se cierra. |
| Proveedor de pago falla | Servicio finalizado; integración de pagos falla. | POST al endpoint de cierre. | El cierre queda registrado según política de consistencia; estadoPago refleja error/pendiente y nunca CONFIRMADO sin confirmación externa. |
